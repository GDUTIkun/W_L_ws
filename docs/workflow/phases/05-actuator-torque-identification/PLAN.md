# Phase 05: 执行器力矩辨识与模型校准 — PLAN

Status: `active`

## Goal

建立可复现、可审查且可复用于不同执行器的力矩辨识链路，得到静态力矩映射、摩擦和输出轴等效惯量；先以 3508+C620 跑通完整垂直切片，再覆盖 GIM6010，并为 MuJoCo 执行器参数校准提供真实证据。

## Current State

- 已有：[`拆机力矩测试`](../../../mujoco/拆机力矩测试.md) 已定义静态力矩、摩擦和空载惯量三类实验及 `r = 0.2 m` 的当前夹具设想。
- 已有：STM32 中已有 3508+C620、GIM6010 的力矩命令、位置/速度/估算力矩反馈，以及 UART2 候选实验链路。
- 已提供旧接口与现场记录：`docs/temp/stm32_ros_comm_task.md` 记录了 ROS2↔STM32 V1 的帧协议和联调结果，但旧 ROS package 源码及其 `wheel_leg_msgs`/`wheel_leg_common` 依赖未进入当前仓库；T02 已据此实现等价实验入口，仍需真实构建和联调验证。
- 已有：实际测力数据由独立串口/USB Load Cell 进入电脑，适合由主机侧统一采集、记录和分析。
- 缺少：辨识专用安全执行模式、请求值与实际施加值/原始电流的可追溯遥测、双数据源时间对齐、正式数据包、拟合工具、重复性评价和 MuJoCo 校准证据。
- 当前代码风险：3508+C620 小电流命令包含 `Threshold_Current` 补偿；若不区分测试模式，会把软件补偿混入执行器本体的死区和摩擦辨识。
- 代码证据：[`dvc_motor_dji.cpp`](../../../../firmware/stm32/Hardware/dvc_motor_dji.cpp)、[`dvc_motor_dji.h`](../../../../firmware/stm32/Hardware/dvc_motor_dji.h)、[`uart_protocol_test.cpp`](../../../../firmware/stm32/App/uart_protocol_test.cpp)、[`Car.cpp`](../../../../firmware/stm32/App/Car.cpp)。

## Scope

- 将现有拆机方案整理为正式、可复用的多执行器实验规程，覆盖静态力矩映射、启动力矩、低速 Coulomb 摩擦和输出轴等效惯量。
- 建立主机侧试验编排、USB/串口 Load Cell 采集、STM 遥测采集、原始数据落盘、离线对齐、拟合、可视化和报告链路。
- 建立 STM32 辨识专用执行路径：单执行器选择、其余执行器强制零输出、限幅、斜率限制、命令超时、急停以及必要的原始命令/反馈遥测。
- 第一执行批次使用 3508+C620，先完成低风险链路跑通，再完成其三类正式辨识与重复性检查。
- 3508+C620 链路通过后，以相同数据契约和证据标准扩展到 GIM6010；器件特有的命令换算和安全限值允许由配置表达。
- 形成带适用条件、单位、方向、固件/脚本版本和不确定度说明的逐执行器参数集，并在 MuJoCo 基础模型可用后完成对应参数校准与比较。
- 本 Phase 的所有真机执行均以前置 [Phase 14 MuJoCo 内部动力学验证](../14-mujoco-internal-dynamics-validation/PLAN.md) REVIEW PASS 为条件；前置门关闭前只保留现有实现和文档，不继续板级联调、pilot 或正式实验。

## Out of Scope

- 电机内部电阻、电感、反电动势常数、驱动器电流环等完整电机模型辨识。
- 腿、轮、连杆、车体等外部结构的质量、COM、完整关节惯量和动力学耦合辨识。
- 冻结树莓派—STM32 的生产通信协议、统一 RobotState/TorqueCommand 精确 schema 或六关节正式顺序。
- WBC、NMPC、Joint PD、重力补偿和整机闭环控制开发。
- 用代码完成或单次曲线替代真实实验重复性、测量质量和模型一致性证据。

## Frozen Decisions

- 分层固定为：STM32 负责确定性实时执行、底层安全和同源状态采样；ROS2/电脑负责试验编排、Load Cell 采集、数据记录与离线分析。
- Load Cell 独立通过串口/USB 接电脑；不为本 Phase 把 Load Cell 数据绕回 STM32。
- 所有正式数据同时保留 STM 时间戳/序号与电脑单调时钟；不得把 ROS/USB 接收时刻直接解释成无延迟的物理采样时刻。
- 力矩真值来自经校准 Load Cell 与有效垂直力臂：`tau_real = F * r_perp`。C620/GIM6010 的驱动反馈或电流换算力矩只作为解释变量，不作为力矩真值。
- 必须分别记录 `tau_requested`、STM 安全/限幅/斜率处理后的 `tau_applied`、最终驱动器原始命令以及驱动器原始反馈；不得只记录上位机请求值。
- 3508+C620 的本体基线辨识禁用 `Threshold_Current` 软件补偿。若需评估补偿模式，必须作为独立配置和独立数据批次，不能与本体基线混合拟合。
- 惯量实验的阶跃时序由 STM 本地执行或由等价的确定性底层机制执行；普通 ROS/USB 消息到达抖动不能定义阶跃边沿。
- 不对编码器位置直接连续差分两次；加速度从明确窗口内的运动模型拟合获得，并报告窗口、残差和不确定度。
- 执行顺序固定为：3508+C620 链路跑通 → 3508+C620 正式辨识 → GIM6010 适配与正式辨识 → MuJoCo 参数校准。
- 上述执行顺序整体位于 Phase 14 之后；Phase 14 未 PASS 时不得以“软件已写好”绕过 MuJoCo-only Gate B 接触真机。
- 本 Phase 的实验消息/协议扩展是测试接口，不自动升级为生产协议。

## Open Questions / Decision Gates

- **DG01 通信资产 grounding：** 现有 ROS2↔STM 通信层进入仓库或提供可追溯源码版本后，确认运行入口、字段、频率、时间语义和丢帧检测；关闭前不得声称端到端采集已验证。
- **DG02 Load Cell 计量能力：** 正式实验前确认设备型号、量程、采样率、串口协议、标定系数、零漂、噪声与过载保护；未经校准的数据只能用于链路调试。
- **DG03 采样和同步：** 用一次低风险 pilot 测量 STM 遥测与 Load Cell 的实际采样率、抖动和相对延迟，冻结对齐方法。pilot 数据不得直接充当正式辨识证据。
- **DG04 定量阈值：** 根据设备精度、pilot 噪声和重复性，在正式批次之前冻结稳定窗口、拟合残差、重复性和 MuJoCo 对应误差阈值；不得根据正式结果反向放宽阈值。
- **DG05 安全包络：** 分别冻结 3508+C620 与 GIM6010 的电流/力矩、速度、行程、持续时间和温升上限，并经空载低幅测试确认急停与超时归零。
- **DG06 GIM6010 夹具与命令语义：** 在完成 3508 垂直切片后，确认 GIM6010 的安装、输出轴方向、反馈量含义和可用力矩范围，再开始其正式批次。
- **DG07 / CLOSED MuJoCo 前置验证：** Phase 14 已证明 nominal MuJoCo plant 内部自洽并 REVIEW PASS。该结论只解除本前置 blocker，不替代 DG01–DG06、真机计量质量或 MuJoCo–real 对应证据。

## Interfaces and Compatibility

- 输入：执行器配置、测试类型、带单位的激励序列、安全上限、Load Cell 标定参数和夹具有效力臂。
- STM 输出遥测：至少包含执行器标识、样本序号、STM 时间、`tau_requested`、`tau_applied`、驱动器原始命令、原始电流/反馈、`q`、`dq`、在线与安全状态。
- 主机原始记录：STM 原始帧/解码值、Load Cell 原始帧/力值、电脑单调接收时间、试验事件与完整元数据；`raw/` 采集后不可手工编辑。
- 分析输出：对齐后的表格、拟合参数、残差、置信/不确定度、重复性统计、图和机器可读参数文件。
- 单位：力 `N`、长度 `m`、输出轴力矩 `N·m`、输出轴角度 `rad`、输出轴角速度 `rad/s`、时间 `s`；原始计数同时保留且不得被覆盖。
- 必须保持：当前机器人运行路径默认行为不因辨识模式而静默改变；辨识模式显式进入、单执行器授权、退出/超时归零。
- 允许改变：实验候选通信字段、辨识专用固件路径、主机实验工具和分析格式；所有变化需版本化且不宣称为生产接口。

## Validation Plan

### Automated

- STM32：使用 T02 grounding 后确认的真实工程构建入口编译；辨识模式相关的帧编解码、限幅、单路隔离、超时和状态转换测试必须通过。
- ROS2/主机：使用入仓通信层的真实构建与测试入口；采集器的模拟串口、丢帧、CRC/解析错误、断连和安全停机测试必须通过。
- 分析：以合成参数生成带噪、缺样和时钟偏移数据，验证静态映射、摩擦、加速度拟合和惯量估计能够在预设误差内恢复真值。
- 数据：自动检查必需字段、单位、时间单调性、序号缺口、饱和、稳定窗口、原始数据只读约定及元数据完整性。
- T02 必须在 Execution Notes 中记录上述验证的精确命令；当前仓库尚无足以诚实填写的 ROS2/STM32 完整构建命令，不在 PLAN 中虚构入口。

### Manual / Evidence

- 每个正式 run 使用 `data/experiments/YYYY-MM-DD-<actuator>-torque-identification/`，README 记录 Phase、Git commit、固件、ROS/脚本版本、执行器/驱动器序列信息、Load Cell 标定、夹具尺寸、配置、操作员和环境条件。
- 安全验证先于辨识：机械固定、急停、超时归零、命令为零、其余通道为零、限位/速度/温升保护均需实际检查。
- 静态映射：正负多点、零点和重复循环，保留加载/卸载方向以识别偏置、死区、非对称和迟滞。
- 摩擦：正反方向分别测启动力矩和低速匀速拖动力矩，记录电机使能状态和实际速度区间。
- 惯量：拆除力臂和外载，在安全短时窗口执行多档正负阶跃；用预先规定窗口拟合 `q(t)`，检查饱和、速度依赖和拟合残差。
- 每个结论都链接真实 raw、processed、figures 和质量报告；失败 run 保留元数据并标明无效原因，不选择性删除。
